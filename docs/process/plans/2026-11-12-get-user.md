# `get_user` Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a read-only MCP tool `get_user` that returns curated profile details for one Telegram user, looked up by `user_id` or `username`.

**Architecture:** A pure mapping function turns gotd `*tg.User` + `*tg.UserFull` into `tg.UserInfo`. `Service.GetUser` resolves an `InputUser` (peer cache / dialog scan, or `contacts.resolveUsername`), calls `users.getFullUser`, and maps the result. `mcpserver` validates input and exposes the tool.

**Tech Stack:** Go 1.25, `github.com/gotd/td` v0.163.0 (`tg`, `tgerr`, `tgmock`), `github.com/modelcontextprotocol/go-sdk` v1.8.0.

**Spec:** `docs/process/specs/2026-11-12-get-user-design.md`

## Global Constraints

- Read-only: no Telegram write calls. Tool annotation `ReadOnlyHint: true`.
- Never log user data (phone, bio, names). Only the tool result carries it.
- Peer cache save failure is a `slog.Warn`, not an error (same as `read_chat`).
- JSON field names and `omitempty` rules exactly as in the spec's `UserInfo`.
- Status values: `online`, `offline`, `recently`, `last_week`, `last_month`, `unknown`.
- Error texts, verbatim:
  - `pass exactly one of user_id or username`
  - `unknown user; pass a chat_id of a private chat from list_chats, or a username`
  - `username belongs to a group or channel, not a user`
  - `username not found`

## Review Focus

1. `users.getFullUser` response whose `Users` lacks the requested id (or holds only `UserEmpty`) → clear error, no nil panic. Test in Task 2.
2. `username` given as `"@Name"` or `"  name  "` → stripped to `Name`/`name` before the call; `"@"` alone → validation error. Test in Task 3.
3. Deleted account (empty first name, `Deleted` flag, no status) → returns with `deleted: true`, `status: "unknown"`. Test in Task 1.
4. User with `Usernames` set and empty `Username` (collectible usernames) → primary is the first active one, not lost. Test in Task 1.
5. Business work hours with an empty `WeeklyOpen` and no address/intro → `business` is nil, not `{}`. Test in Task 1.
